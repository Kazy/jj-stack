jj-stack 0.1.6 fixes PR commits becoming immutable with Git 2.56, and fixes `jj-stack sync` after a partial stack merge.

## Fixes

- With Git 2.56 or newer, PR branches pushed by jj-stack showed up in jj as untracked remote bookmarks, so jj treated your PR commits as immutable and `sync` and `merge` failed with `Commit … is immutable`. If you already pushed with Git 2.56, run `jj-stack doctor --fix` once after upgrading to remove those bookmarks.
- After a partial stack merge, `jj-stack sync` could turn every remaining change into a conflicted divergent copy on the old base, or fail with "Imported pull request heads no longer form the expected stack" if another PR merged in the meantime. It now rebases the remaining changes onto trunk.
- After `jj-stack merge --no-wait`, `jj-stack sync <head-change-id>` no longer stops with "did not resolve to a visible commit" when GitHub deleted the merged PR branches.

## Other changes

- `jj-stack list` and `jj-stack view` say why GitHub is blocking a PR, such as `merge conflicts`, `unresolved review threads`, or `missing required check: <name>`.
- `list`, `cleanup`, and `sync --all` are faster in repos with many PRs or a long history.
